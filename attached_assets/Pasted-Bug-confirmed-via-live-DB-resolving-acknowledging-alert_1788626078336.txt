Bug confirmed via live DB: resolving/acknowledging alerts fails because of an ID mismatch.

restaurant_alerts.resolved_by and restaurant_alerts.acknowledged_by are uuid columns with FOREIGN KEY to employees.id. But the alert update code writes req.user.id, which is the Supabase Auth user id (auth_user_id), NOT the employees row id. The FK rejects the write, so PATCH /api/v1/panel/alerts/:id (and the mirrored write from waiter-calls resolve) fails.

This is the same class of bug as closed_by on table_sessions. Fix it properly and check for the same pattern elsewhere.
